# 版本命名政策

为避免“原始仓库叫 v1、后续版本却叫 v0.4”的歧义，本仓库从 2026-08-07 起采用以下命名：

| 名称 | 含义 |
|---|---|
| `v0` | 原始仓库整体基线，包括原 Phase 0–9 流程、历史文档、报告、证据和工具入口 |
| `v0.1`、`v0.2`、`v0.3` | v0 基线内部已经发布的语义模型版本 |
| `v0.4` | 本轮根据 D 组契约新增的目标版本 |

相应目录采用 `prompts/v0/`、`archive/v0_*/` 和 `docs/v0.4/`。今后的现行文档不得再用 “v1” 指代原始仓库。

## 不应改名的 `v1`

以下字符串不表示仓库代际，因此保持不变：

- 冻结来源的旧物理目录名 `v1_docs/`：只在 provenance 中作为来源路径引用；迁入后的概念目录是 `archive/v0_docs/`。
- `building-energy-hourly-v1`：场景中的 Dataset ID，不是仓库版本号。
- `https://www.w3.org/2018/credentials/v1`：外部标准 URI。
- 两份冻结 ZIP 及其他冻结文件内部的历史文字：为保持字节级完整性不回写；出现旧称时按本政策解释为 v0 基线的历史命名。

若未来需要真正的仓库级 v1，应在 v0.4 之后另行定义发布边界，不能把当前原始仓库追认成 v1。
